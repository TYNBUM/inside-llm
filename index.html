如何学习这门课程How to use this course

这门课面向已经会用聊天模型、提示词、API 和智能体，但还说不清“隐藏层、注意力头、权重”到底是什么的学习者。它不从公式出发，也不停留在“切成 token、预测下一个 token”的概述，而是一步步把你带到能读懂简单公式、张量形状、架构图和伪代码的程度。

This course is for people who already use chat models, prompts, APIs and agents, but cannot yet say what a hidden layer, an attention head or a weight actually is. It does not start from formulas, and it does not stop at “split into tokens, predict the next token”. It moves you, step by step, to the point where simple formulas, tensor shapes, architecture diagrams and pseudocode become readable.

每个主要概念都走同一条路Every major concept follows the same path

① 问题：是什么困难催生了这个机制？② 直觉：用日常语言说清思路。③ 实际对象：它到底是一组数、一个矩阵、一个运算、一个存储的参数，还是运行时的数据结构？④ 可见的过程：输入、中间变化、输出。⑤ 最小数值例子：完整算一遍。⑥ 与真实模型的联系：哪些能推广，哪些被简化了。⑦ 理解检查：先预测，再看解释。

(1) The problem: what difficulty motivates the mechanism? (2) The intuition, in plain language. (3) The actual object: a list of numbers, a matrix, an operation, a stored parameter, or a runtime data structure? (4) The visible process: inputs, intermediate changes, outputs. (5) A minimal numerical example, worked completely. (6) The connection to real models: what carries over and what was simplified. (7) A comprehension check: predict first, then read the explanation.

第 1 部分 · 1.1Part 1 · 1.1

程序、参数与计算：一个模型由哪三样东西组成Program, Parameters, Computation: The Three Things a Model Is Made Of

≈ 10 min前置：无（建议先读课程地图中的约定）Prerequisites: none (read the conventions on the course map first)

1问题The problem

我们习惯把软件理解为“程序员写好的规则”：如果用户点了这里，就做那件事。可没有人给语言模型写过“如何回答关于巴黎的问题”的规则。那么，模型的行为到底写在哪里？如果它不在代码里，代码又负责什么？

We are used to thinking of software as rules a programmer wrote: if the user clicks here, do that. Yet nobody wrote a rule telling a language model how to answer a question about Paris. So where does the model's behaviour live? And if it is not in the code, what is the code for?

2直觉The intuition

想象一张带空格的计算表：表格的结构（先乘哪几个数、再加起来、再比较）是固定的，空格里要填的数却来自另一份文件。换一份文件，同一张表就算出完全不同的结果。语言模型的代码就是这张计算表的结构；模型权重文件就是填空用的数；而“这次输入算出来的所有中间结果”是第三样东西，每次运行时才产生。

Picture a worksheet with blanks. Its structure (which numbers to multiply, then add, then compare) is fixed, but the numbers that go into the blanks come from a separate file. Swap the file and the same worksheet produces entirely different results. A language model's code is the worksheet's structure; the weights file supplies the numbers for the blanks; and “all the intermediate results for this particular input” are a third thing, produced only when the computation runs.

类比的边界：真实的“计算表”极其规整，几乎全是重复的矩阵乘法，结构本身并不“知道”任务是什么；填进去的数有几十亿个，没有一个是人填的，全部来自训练。所以不要想象成“表格结构里藏着聪明的规则”。

Where the analogy stops: the real worksheet is extremely regular, almost entirely repeated matrix multiplications, and its structure “knows” nothing about the task. The numbers that fill it run into billions, none chosen by a person; all of them come from training. So do not imagine clever rules hidden in the worksheet's structure.

5最小例子A minimal example

输入 (1, 1)。文件 A（异或）：输出 0。文件 B（与）：输出 1。文件 C（或）：输出 1。同样的四行代码，同样的输入，结果取决于填进去的数。更关键的是：如果有人只给你这三份文件、不告诉你名字，你只能通过运行它们来知道各自做什么，从数字本身很难一眼看出来。真实模型更是如此。

Input (1, 1). File A (XOR): output 0. File B (AND): output 1. File C (OR): output 1. Same four lines of code, same input; the result depends on the numbers filled in. More importantly, if someone handed you the three files without their names, you could only find out what each does by running it; it is hard to see from the numbers alone. That is even more true of real models.

6与真实模型的联系Connection to real models

在 Hugging Face 的 transformers 库中，一个名为 LlamaForCausalLM 的类既能运行 Llama 2 7B，也能运行 13B 和 70B：区别只在于 config.json 中的数字和权重文件。推理引擎（如 vLLM、llama.cpp）也是如此。所以“开源模型”通常指公开的权重（加上配置和分词器），而运行它的代码往往是通用的。

In Hugging Face's transformers library, a single class called LlamaForCausalLM runs Llama 2 7B, 13B and 70B; the only differences are the numbers in config.json and the weight files. Inference engines such as vLLM and llama.cpp work the same way. So an “open model” usually means published weights (plus config and tokenizer), while the code that runs it is often generic.

通用原理General principle

模型“知道”的东西，以分布在大量参数中的数值形式存在，而不是以可读的规则或数据库条目形式存在。这就是为什么无法通过“搜索代码”找到模型的某个行为，也是为什么修改模型行为通常要通过再训练（第 6 部分），而不是改代码。

What a model “knows” exists as numbers spread across many parameters, not as readable rules or database entries. That is why you cannot find a behaviour by searching the code, and why changing a model's behaviour usually means further training (Part 6) rather than editing code.

7理解检查Comprehension check

1.2

文本为何要变成数字：表示的含义Why Text Becomes Numbers: What a Representation Is

≈ 10 min前置：1.1Prerequisites: 1.1

1问题The problem

计算表只能处理数字，所以文字必须先变成数字。问题是：变成什么样的数字，后续的乘法和加法才有意义？一个编号（比如“猫”= 5012）可以区分不同的词，但对编号做算术毫无意义：5012 + 1 不是“更像猫的东西”，5012 × 2 也不是任何东西。

The worksheet only handles numbers, so text must first become numbers. The question is: which numbers make the later multiplications and additions meaningful? An ID (say “cat” = 5012) can tell words apart, but arithmetic on IDs means nothing: 5012 + 1 is not “something more cat-like”, and 5012 × 2 is not anything at all.

2直觉The intuition

如果给每个词一串数（一个向量），并且让用法相似的词得到相似的数串，那么算术就有了意义：两个向量的点积大，就说明它们相似；向量相加可以“混合”信息；矩阵乘法可以把一种描述改写成另一种。这样的一串数叫做这个词（或这个位置）的表示。表示是模型内部所有计算的“原材料”。

Give each word a list of numbers (a vector), arranged so that words used in similar ways get similar lists, and arithmetic becomes meaningful: a large dot product between two vectors signals similarity; adding vectors mixes information; matrix multiplication rewrites one description into another. Such a list of numbers is the representation of that word (or position). Representations are the raw material of every computation inside the model.

3实际对象The actual object

一个表示就是形状为 [d] 的浮点数组。它有两种来源：(1) 初始表示来自一张参数表，每个 token 对应一行（嵌入表，4.2）；(2) 上下文表示由各层计算得到，同一个 token 在不同句子里会得到不同的向量（4.5）。数值本身是训练过程塑造的：训练只要求“这些数能帮助预测下一个 token”，从未要求某一维表示某个人类概念。

A representation is a floating-point array of shape [d]. It has two sources: (1) the initial representation comes from a parameter table with one row per token (the embedding table, 4.2); (2) contextual representations are computed by the layers, so the same token gets different vectors in different sentences (4.5). The numbers themselves are shaped by training, which only asks that they help predict the next token; it never asks any dimension to stand for a human concept.

4可见的过程The visible process

实验 1.2：同一组 6 维向量，换一对坐标轴来画Lab 1.2: the same 6-dimensional vectors, drawn on different pairs of axes编造的玩具向量invented toy vectors

点一个词，右表按完整 6 维的 cos 相似度排序。然后换坐标轴：在某些二维图里“老虎”离“汽车”比离“狗”还近，但 6 维中的真实相似度从未改变。二维图丢掉了其余 4 维的信息。

Click a word; the table ranks the others by cosine similarity over all 6 dimensions. Then change the axes: in some 2D views “tiger” sits closer to “car” than to “dog”, yet the true 6-D similarity never changes. A 2D picture throws away the other 4 dimensions.

这些向量是我们编造的，维度 d1–d6 没有名字。真实模型的向量有几百到几千维，常见的二维图（如 PCA、t-SNE）都是这种有损投影，只能作为示意。We invented these vectors; dimensions d1–d6 have no names. Real model vectors have hundreds to thousands of dimensions, and common 2D plots (PCA, t-SNE) are lossy projections of this kind, useful only as illustrations.

5最小数值例子A minimal numerical example

只用 d1、d2 两维：猫 = (0.9, 0.8)，老虎 = (0.9, 0.2)，汽车 = (0.0, 0.1)。在这个平面上老虎离猫的距离是 0.6，离汽车约 0.91。再改用 d2、d3：猫 = (0.8, 0.1)，老虎 = (0.2, 0.1)，汽车 = (0.1, 0.9)，老虎与猫的距离仍是 0.6，但与汽车的距离变成约 0.81。用全部 6 维计算 cos：cos(猫, 老虎) ≈ 0.78，cos(猫, 汽车) ≈ 0.14，cos(猫, 狗) ≈ 0.98（实验中有精确值）。投影改变的是“看上去的”远近，不是向量本身。

Use only d1 and d2: cat = (0.9, 0.8), tiger = (0.9, 0.2), car = (0.0, 0.1). In this plane tiger is 0.6 from cat and about 0.91 from car. Switch to d2 and d3: cat = (0.8, 0.1), tiger = (0.2, 0.1), car = (0.1, 0.9); tiger is still 0.6 from cat but now about 0.81 from car. Over all 6 dimensions, cos(cat, tiger) ≈ 0.78, cos(cat, car) ≈ 0.14 and cos(cat, dog) ≈ 0.98 (the lab shows exact values). Projection changes how near things look, not the vectors themselves.

6与真实模型的联系Connection to real models

在真实模型中，“相似的词得到相似的向量”不是人为安排的，而是训练的副产品：为了预测下一个 token，用法相近的词往往被推向相近的方向。但相似性是多方面的（“猫”与“狗”都是宠物，“猫”与“老虎”都是猫科），单一的远近关系无法概括。同时，向量中的信息并不按维度整齐排列。

In real models, “similar words get similar vectors” is not arranged by anyone; it is a by-product of training. To predict the next token, words used in similar ways tend to be pushed toward similar directions. But similarity has many facets (cat and dog are both pets; cat and tiger are both felines), and a single notion of nearness cannot capture them all. Nor is the information neatly laid out one dimension per property.

深入 D1（可选，约 10 分钟）：叠加假说——为什么维度不是概念Deeper D1 (optional, about 10 min): the superposition hypothesis, or why dimensions are not concepts

如果模型需要表示的“特征”（可区分的性质）比维度还多，它能怎么办？Elhage 等（2022）用很小的玩具模型展示：当特征很稀疏（大多数时候只有少数特征同时出现）时，模型会把多个特征放在彼此不完全正交的方向上，容忍一点相互干扰，以换取能表示更多特征。这称为叠加。

What can a model do if it needs to represent more “features” (distinguishable properties) than it has dimensions? Elhage et al. (2022) showed in small toy models that when features are sparse (only a few are active at once), the model places several features along directions that are not exactly orthogonal, tolerating a little interference in exchange for representing more features. This is called superposition.

这与 2.2 的事实相连：高维空间中可以容纳大量“几乎正交”的方向（4096 维中两个随机方向的 cos 典型值约 0.016）。后果是：(1) 单个维度或单个神经元往往同时参与多个特征，看起来是“多义的”；(2) 想找到干净的特征，需要寻找方向而不是坐标轴，这就是“稀疏自编码器”等方法的出发点（见 D9）。

This connects to a fact from 2.2: high-dimensional space has room for very many “nearly orthogonal” directions (two random directions in 4096 dimensions have a typical cos of about 0.016). Consequences: (1) a single dimension or neuron often takes part in several features and looks “polysemantic”; (2) finding clean features means searching for directions rather than axes, which motivates methods such as sparse autoencoders (see D9).

不确定性Uncertainty

叠加在玩具模型中得到了清晰展示；它在大型语言模型中到底多普遍、以什么形式出现，仍是活跃的研究问题。

Superposition is clearly demonstrated in toy models; how widespread it is in large language models, and in what form, is still an active research question.

7理解检查Comprehension check

1.3

模型文件里有什么，运行时又多了什么What a Model File Holds, and What Appears at Runtime

≈ 12 min前置：1.2Prerequisites: 1.2

1问题The problem

下载一个模型时，你得到的是几个文件。运行它时，显存占用往往比文件大不少，而且会随着对话长度和用户数变化。这些多出来的东西是什么？输入的文字又去了哪里？常见的误解是“输入进入了权重文件”。事实上，权重文件在推理时只被读取，从不被写入。

When you download a model you get a few files. When you run it, memory use is often noticeably larger than the files, and it changes with conversation length and number of users. What is the extra? And where does the input text go? A common misconception is that “the input goes into the weights file”. In fact the weights file is only ever read during inference, never written.

2直觉The intuition

把参数想成一台机器的固定零件，把输入想成流过机器的原料。零件在开机时装好（从磁盘读到内存），之后一直不变；原料每次不同，在加工过程中会产生很多半成品（激活值），有些半成品要留到这次任务结束（KV 缓存）。类比的边界：机器零件不会因为原料而改变，这一点准确；但真实系统里“半成品”占的空间可能比零件还大，这是普通机器类比里没有的。

Think of parameters as the fixed parts of a machine and the input as raw material flowing through it. The parts are installed at start-up (read from disk into memory) and then never change. The material differs each time, and processing creates many intermediate products (activations); some must be kept until the job ends (the KV cache). Where the analogy stops: it is accurate that the parts do not change because of the material; but in real systems the intermediate products can take more space than the parts, which an ordinary machine analogy does not suggest.

参数量衡量的是什么What a Parameter Count Measures

≈ 8 min前置：1.3Prerequisites: 1.3

1问题The problem

“7B”“70B”这样的数字出现在每个模型名里。它数的是什么？它能告诉你什么（显存、速度），不能告诉你什么（知道多少事实、有多聪明）？

Numbers like “7B” and “70B” appear in every model name. What exactly do they count? What do they tell you (memory, speed), and what do they not tell you (how many facts it knows, how capable it is)?

2直觉与实际对象Intuition and actual object

参数量就是所有参数张量中数字个数的总和。它直接决定两件事：存储（参数量 × 每个数的字节数）和每个 token 的计算量：生成一个 token 时，几乎每个权重都要参与一次乘法和一次加法，所以前向计算约为 2 × 参数量 次浮点运算（忽略注意力中与上下文长度有关的部分，见第 5、7 部分）。

The parameter count is the total number of numbers across all parameter tensors. It directly determines two things: storage (parameter count × bytes per number) and compute per token. To produce one token, nearly every weight takes part in one multiply and one add, so a forward pass costs about 2 × parameter count floating-point operations (ignoring the context-length-dependent part of attention, see Parts 5 and 7).

它不衡量“存了多少条知识”。知识不是一条条存进参数的：一个事实的影响分散在许多参数中，同一组参数又参与无数个事实和技能。参数更多通常意味着容量更大，但能力还取决于训练数据的数量与质量、训练计算量和训练方法。Hoffmann 等（2022，“Chinchilla”）的研究显示，在固定计算预算下，较小的模型用更多数据训练可以胜过更大但训练不足的模型。

It does not measure how many facts are stored. Knowledge is not filed into parameters one item at a time: the influence of one fact is spread across many parameters, and the same parameters take part in countless facts and skills. More parameters usually mean more capacity, but capability also depends on the quantity and quality of training data, the training compute, and the training method. Hoffmann et al. (2022, “Chinchilla”) showed that, for a fixed compute budget, a smaller model trained on more data can outperform a larger, under-trained one.

这把参数量拆成两个数：总参数决定存储与显存（所有专家都要加载，因为不知道下一个 token 会选谁）；激活参数决定每个 token 的计算量。所以 MoE 模型可能“显存像大模型，速度像小模型”。读模型说明时，要看清它报的是哪一个数。

标量、向量、矩阵、张量与形状Scalars, Vectors, Matrices, Tensors and Shapes

≈ 12 min前置：1.2Prerequisites: 1.2

1问题The problem

模型文档里到处是 [batch, seq_len, hidden_size] 这样的写法。模型同时处理多个请求、每个请求有多个位置、每个位置有一个向量，需要一种统一的方式来描述“一大块数是怎样排列的”。形状就是这种描述。读懂形状，你就能在看不懂公式时仍然判断一个运算在做什么、是否合法。

Model documentation is full of notation like [batch, seq_len, hidden_size]. A model handles several requests at once, each with several positions, each position carrying a vector, so we need one consistent way to say how a block of numbers is arranged. That description is the shape. If you can read shapes, you can often tell what an operation does, and whether it is valid, even when the formula is unfamiliar.

2直觉The intuition

一个数是标量；一排数是向量；一张表是矩阵；把几张同样大小的表摞起来，就是一个三维的张量，还可以继续往上摞。每多一个“摞起来的方向”，就多一个轴。形状依次写出每个轴的长度。

One number is a scalar; a row of numbers is a vector; a table is a matrix; stack several same-sized tables and you get a three-dimensional tensor, and you can keep stacking. Each new stacking direction adds an axis. The shape lists the length of each axis in order.

三类运算对形状的要求Three kinds of operations and what they need from shapes

(1) 逐元素运算（加法、ReLU 等）：两个张量形状相同，对应位置各算各的，结果形状不变。(2) 广播：形状不同但“可扩展”时，较小的张量被自动重复使用。例如 [n, d] 加偏置 [d]：同一个偏置加到每一行上。这正是 3.2 中“同一个 b 用于所有位置”的实现方式。(3) 矩阵乘法：最后一个轴与对方的第一个轴必须相等并被“消掉”，[n, d] × [d, k] → [n, k]；多出的前置轴（如批次 B）原样保留：[B, n, d] × [d, k] → [B, n, k]。

(1) Element-wise operations (addition, ReLU, etc.): both tensors have the same shape, each position is computed independently, and the shape is unchanged. (2) Broadcasting: when shapes differ but are “expandable”, the smaller tensor is reused automatically. Adding a bias [d] to [n, d] adds the same bias to every row. This is exactly how “the same b for every position” in 3.2 is implemented. (3) Matrix multiplication: the last axis must equal the other operand's first axis, and that axis disappears: [n, d] × [d, k] → [n, k]. Extra leading axes (such as batch B) pass through: [B, n, d] × [d, k] → [B, n, k].

2.22.2

向量与点积：模型用来“比较方向”的基本动作Vectors and the Dot Product: How a Model Compares Directions

≈ 9 min前置：2.1Prerequisites: 2.1

1问题The problem

模型内部只会做算术：乘、加、比大小。可我们要它处理文字。最直接的办法是给每个 token 编号，比如“猫”= 5012。但一个编号只是一个数，它无法同时表达“这是名词”“和动物有关”“出现在句首”“前面有个否定词”等许多方面。更糟的是，编号是任意分配的：5012 和 5013 相邻，并不说明两个词意思接近（第 4 部分会详细讲 token ID）。

Inside a model, the only things that happen are arithmetic: multiplying, adding, comparing. Yet we want it to work with text. The most direct idea is to number each token, say “cat” = 5012. But an ID is one number. It cannot express “this is a noun”, “related to animals”, “at the start of a sentence” and “preceded by a negation” all at once. Worse, IDs are assigned arbitrarily: 5012 and 5013 being adjacent says nothing about whether the words are similar (Part 4 covers token IDs in detail).

所以我们需要一种表示：每个位置都带着很多个数，这些数能用算术来组合和比较。这就是向量。

So we need a representation in which each position carries many numbers that can be combined and compared using arithmetic. That is a vector.

2直觉The intuition

向量就是一串有顺序的数字。两个数字的向量，比如 (2, 1)，可以画成平面上的一个点，或者一支从原点指向这个点的箭头。三个数字对应三维空间中的箭头。数字的个数叫做向量的维度。

A vector is an ordered list of numbers. A two-number vector such as (2, 1) can be drawn as a point in the plane, or as an arrow from the origin to that point. Three numbers give an arrow in 3D space. The count of numbers is the vector's dimension.

类比：屏幕上的颜色可以写成 (红, 绿, 蓝) 三个数，例如 (255, 128, 0) 是橙色。两种颜色是否相近，可以看这三个数是否相近。类比的边界：RGB 的每一格都有人起好的名字（“红”）。语言模型里的向量维度不是人设计的，而是训练过程塑造的；信息通常分散在许多维度的组合上，单个维度一般没有可以直接命名的含义。这个类比只告诉你“一串数可以定位空间中的一个点”，不要把“每格都有名字”也带进来。

Analogy: a screen colour can be written as three numbers (red, green, blue); (255, 128, 0) is orange. Whether two colours are similar can be read from whether their numbers are similar. Where the analogy stops: each RGB slot has a name someone chose (“red”). The dimensions of a language model's vectors are not designed by anyone; training shapes them, and information is usually spread across combinations of many dimensions, so a single dimension generally has no meaning you can name. Keep the part of the analogy that says “a list of numbers locates a point in a space”. Drop the part that says “every slot has a name”.

3实际对象The actual object

在内存里，一个向量就是 d 个连续存放的浮点数，形状记作 [d]。GPT-2 small 在每个位置使用 d = 768 个数，Llama 2 7B 使用 d = 4096。有些向量是每次输入都重新计算的（例如句子中某个位置的中间表示），属于激活值；有些向量是训练后固定存储的（例如某个神经元的权重），属于参数。向量本身只是“一串数”，是参数还是激活值，取决于它从哪里来、什么时候变。

Some vectors are recomputed for every input (for example, the intermediate representation at one position of a sentence); these are activations. Others are stored and fixed after training (for example, a neuron's weights); these are parameters. A vector is just a list of numbers. Whether it is a parameter or an activation depends on where it comes from and when it changes.

模型里反复出现同一个需求：把一个向量和另一个向量比较，得到一个数，表示“这个输入在多大程度上符合我关心的方向”。神经元用它衡量输入与自身权重的匹配（3.1）；注意力用它比较查询与键（第 5 部分）；输出层用它比较最终隐藏状态与每个词表条目（第 6 部分）。完成这个比较的运算叫点积。

One need comes up again and again inside a model: compare one vector with another and get a single number that says how strongly an input lines up with a direction of interest. A neuron uses it to measure how well its input matches its weights (Section 3.1). Attention uses it to compare queries with keys (Part 5). The output layer uses it to compare the final hidden state with each vocabulary entry (Part 6). The operation is called the dot product.

通用原理General principle

The dot product is the most common operation in a language model. A matrix multiplication is a batch of dot products (Section 2.3), and most of a model's compute time is spent in matrix multiplications.

你可能读到过“词向量里某个方向代表性别”之类的说法。研究确实发现，有些可解释的性质大致对应向量空间中的某些方向（多个维度的组合），但很少对应单个维度。可解释性研究还提出了“叠加”假说：模型可能用比维度数更多的“特征方向”来表示信息，彼此部分重叠（Elhage 等，2022）。这是活跃的研究领域，结论仍在发展中。课程中你不会看到“第 17 维表示复数”这类说法。

You may have read claims such as “one direction in word-vector space encodes gender”. This is an active research area and its conclusions are still developing. You will not see claims like “dimension 17 means plural” in this course.

一个人工神经元：点积、偏置与激活函数One Artificial Neuron: Dot Product, Bias, Activation Function

1问题The problem

我们有一个输入向量 x。我们想算出一个新的数，它在输入呈现某种模式时变大、否则保持很小；并且“对什么模式敏感”这件事必须可以调节，这样训练才能把它调成有用的样子。点积已经能衡量“x 与某个方向的对齐程度”，但还缺两样东西：一个可以移动的门槛，以及一种“低于门槛就不响应”的机制。

We have an input vector x. We want to compute a new number that grows when the input shows a certain pattern and stays small otherwise; and which pattern it responds to must be adjustable, so that training can tune it into something useful. The dot product already measures how well x lines up with a direction. Two things are missing: a threshold that can be moved, and a way to “not respond” below that threshold.

2直觉The intuition

把神经元想成一次加权投票：每个输入分量都有一张选票，权重决定这张票有多重、是投赞成（正）还是反对（负）；偏置是一个与输入无关的基础分，相当于把门槛整体上移或下移；最后由激活函数决定如何把总分变成输出，例如“总分为负就输出 0”。

Think of a neuron as a weighted vote. Each input component casts a ballot; its weight sets how heavy the ballot is and whether it votes for (positive) or against (negative). The bias is a base score that does not depend on the input, which shifts the threshold up or down. Finally an activation function decides how the total becomes the output, for example “output 0 if the total is negative”.

“神经元”这个名字的边界：它源自对生物神经元的早期粗略模仿。真实神经元会放电、有时间动态和化学过程；人工神经元只是下面这个公式，没有更多东西。理解它时请以公式为准，而不是以生物学想象为准。

Limits of the name “neuron”: it comes from an early, rough imitation of biological neurons. Real neurons spike and have timing and chemistry. An artificial neuron is exactly the formula below and nothing more. When reasoning about it, trust the formula, not the biological picture.

一层：许多神经元同时计算，就是一次矩阵乘法A Layer: Many Neurons at Once Is One Matrix Multiplication

1问题The problem

一个神经元只产出一个数。但下一步计算需要的是一个新的向量：许多个不同的“特征”，各自衡量输入的不同方面。办法很直接：让 dout 个神经元读同一个输入 x，每个神经元有自己的权重和偏置，把它们的输出排成一个向量。问题在于如何把这件事写得简洁、算得高效。

A neuron produces one number. The next computation needs a new vector: many different “features”, each measuring a different aspect of the input. The fix is direct: let dout neurons read the same input x, each with its own weights and bias, and line their outputs up as a vector. The question is how to write this compactly and compute it efficiently.

2直觉The intuition

把每个神经元的权重向量竖着写成一列，并排放在一起，就得到一张数表，这就是矩阵。第 j 列就是第 j 个神经元的权重。计算这一层，就是让 x 与每一列做一次点积。“矩阵乘法”只是“成批的点积”的名字。

Write each neuron's weight vector as a column and place the columns side by side. The resulting table of numbers is a matrix; column j holds neuron j's weights. Computing the layer means taking the dot product of x with every column. “Matrix multiplication” is simply the name for this batch of dot products.

隐藏层：把一层的输出交给下一层Hidden Layers: Handing One Layer's Output to the Next

≈ 10 min前置：2.3Prerequisites: 2.3

1问题The problem

一层能算出一组特征，每个特征都是“输入的加权和，再过一次门槛”。有些任务需要的是由特征组合出的特征。最经典的小例子是异或（XOR）：两个输入都是 0 或 1，恰好有一个为 1 时输出 1，否则输出 0。“恰好一个”不是单纯的“越多越好”，而是“至少一个”且“不是两个都”。我们来看两层网络如何先算出这两个中间特征，再把它们组合起来。

One layer computes a set of features, each “a weighted sum of the input, passed through one threshold”. Some tasks need features built out of features. The classic small example is XOR: two inputs, each 0 or 1; output 1 when exactly one input is 1, otherwise 0. “Exactly one” is not “the more the better”. It is “at least one” and “not both”. Let us see how a two-layer network first computes those two intermediate features and then combines them.

2直觉The intuition

第一层把输入改写成一组新的数，第二层只看这组新数，再算出自己的输出。层与层之间传递的只有激活值向量；第一层的权重不会“流”到第二层。隐藏层中的“隐藏”并不是保密或不可知：你随时可以把这些数打印出来。它的意思是：训练数据里只规定了输入和期望输出，没有人规定中间这些数应该是多少，它们完全由训练出来的参数决定。

The first layer rewrites the input as a new set of numbers; the second layer looks only at those new numbers and computes its own output. Only the activation vector passes between layers; the first layer's weights never “flow” into the second. The “hidden” in hidden layer does not mean secret or unknowable: you can print these numbers at any time. It means that the training data specifies only inputs and desired outputs, and nobody specifies what the intermediate numbers should be. They are determined entirely by the learned parameters.

宽度与深度Width and depth

宽度是一层里有多少个神经元，也就是这一层激活值向量的维度；深度是有多少层依次相连。加宽让一层能并列计算更多特征；加深让后面的层能在前面算出的特征之上再组合。两者在硬件上的代价也不同：同一层内的计算可以并行，但第 k 层必须等第 k−1 层算完。因此在生成每个 token 时，层数会直接影响延迟（第 7.4 章）。

Width is how many neurons a layer has, which is the dimension of its activation vector. Depth is how many layers are chained in sequence. Widening lets a layer compute more features side by side; deepening lets later layers build on features computed earlier. They also cost differently on hardware: computation within a layer can run in parallel, but layer k must wait for layer k−1 to finish. So when generating each token, the number of layers directly affects latency (Chapter 7.4).

“第几层负责什么”是误导性说法“Layer N does X” is misleading

有研究用“探针”（在某层的激活值上训练一个小分类器）发现，某些语言信息在中间层更容易被读出（例如 Tenney 等 2019 对 BERT 的研究）。但这描述的是统计倾向：哪里更容易读出某种信息，并且会因模型而异。它不意味着某一层是“语法模块”。在 Transformer 中，各层的输出不断加回同一个共享向量（残差流，第 4.4 章），信息分布在许多层中。我们没有可靠的方法给每一层指定一个固定职责。

Studies that train “probes” (small classifiers on one layer's activations) find that some linguistic information is easier to read out at middle layers (for example Tenney et al., 2019, on BERT). That describes a statistical tendency about where information is easiest to decode, and it varies by model. It does not mean any layer is “the grammar module”. In a Transformer, every layer's output is added back into one shared vector (the residual stream, Chapter 4.4), and information is spread across many layers. There is no reliable way to assign each layer a fixed responsibility.

语言模型中，“宽度”通常指每个位置向量的维度，配置文件里叫 hidden_size 或 d_model（GPT-2 small 为 768，Llama 2 7B 为 4096）。“深度”是 Transformer 块的数量，叫 num_hidden_layers 或 n_layer（分别为 12 和 32）。注意：Transformer 中的一“层”是一个包含注意力和 MLP 的块，比本节的“一层”复杂；本节的两层网络正是每个块内 MLP 子层的结构。

为什么必须有非线性：没有它，再多层也只是一层Why Nonlinearity Matters: Without It, Many Layers Are Just One

≈ 10 min前置：2.3、3.3Prerequisites: 2.3 and 3.3

1问题The problem

激活函数看起来像一个附带的小细节。如果把它去掉，只把线性层一层层叠起来，网络会不会照样变得更强？答案是不会。这一节先用数字说明原因，再用一张图看清它在几何上意味着什么，最后证明为什么没有非线性就无法计算 XOR。

The activation function looks like a minor add-on. If we removed it and simply stacked linear layers, would the network still become more powerful? It would not. This section shows why with numbers, then with a picture of what it means geometrically, and finally proves why XOR cannot be computed without a nonlinearity.

2直觉The intuition

线性变换对空间做的事只有拉伸、旋转、翻转、剪切：直线仍是直线，平行线仍平行，原点不动。连续做两次这样的变换，结果仍是一次这样的变换，就像连续两次缩放照片等于一次缩放。再加上平移（偏置），叫仿射变换，同样“两次合成一次”。非线性函数则能折弯空间：ReLU 把负半边压平到 0，相当于把纸沿坐标轴折起来。折痕让后面的层可以对不同区域做不同的事。

A linear map can only stretch, rotate, flip and shear space: straight lines stay straight, parallel lines stay parallel, and the origin stays put. Doing two such maps in a row is again one such map, just as scaling a photo twice equals scaling it once. Adding a shift (the bias) gives an affine map, and the same “two compose into one” holds. A nonlinear function can fold space: ReLU flattens the negative side to 0, like folding paper along an axis. The creases let later layers treat different regions differently.

3实际对象与证明The actual object, and the argument

去掉激活函数后，两层网络是 y = (x W₁ + b₁) W₂ + b₂。把括号展开（矩阵乘法满足分配律和结合律）：

With the activation removed, a two-layer network is y = (x W₁ + b₁) W₂ + b₂. Expand the brackets (matrix multiplication is distributive and associative):

y = x (W₁ W₂) + (b₁ W₂ + b₂) = x W + b

这正是一个仿射层，其中 W = W₁W₂，b = b₁W₂ + b₂。形状：W₁ 是 [d₀, d₁]，W₂ 是 [d₁, d₂]，乘积 W 是 [d₀, d₂]，中间维度 d₁ 消失了。同样的论证可以重复任意多次：100 个纯线性层也等价于 1 个。

That is exactly one affine layer, with W = W₁W₂ and b = b₁W₂ + b₂. Shapes: W₁ is [d₀, d₁], W₂ is [d₁, d₂], and the product W is [d₀, d₂]; the middle dimension d₁ disappears. The same argument repeats any number of times: 100 purely linear layers are equivalent to 1.

Now multiply the matrices first: row 1 of W₁W₂ = (1×2 + 2×1, 1×0 + 2×1) = (4, 2); row 2 = (0×2 + 1×1, 0×0 + 1×1) = (1, 1). Directly, x(W₁W₂) = (4 + 1, 2 + 1) = (5, 3), identical to the two-step result.

现在取 x = (−1, 1)。纯线性：x W₁ = (−1, −2 + 1) = (−1, −1)，再乘 W₂ 得 (−3, −1)；合并矩阵也给出 (−4 + 1, −2 + 1) = (−3, −1)。加入 ReLU 后：(−1, −1) 先变成 (0, 0)，最终输出 (0, 0)。而 x = (1, 1) 的中间结果 (1, 3) 全为正，ReLU 不改变它，输出仍是 (5, 3)。同一个网络，对一部分输入“像线性”，对另一部分输入完全不同，这就是折痕的效果。打开实验 E 的 ReLU 开关，看 ◆ 落到哪里。

Now take x = (−1, 1). Purely linear: x W₁ = (−1, −2 + 1) = (−1, −1), then times W₂ gives (−3, −1); the combined matrix also gives (−4 + 1, −2 + 1) = (−3, −1). With ReLU: (−1, −1) first becomes (0, 0), and the final output is (0, 0). Meanwhile x = (1, 1) has intermediate (1, 3), all positive, which ReLU leaves alone, so its output is still (5, 3). The same network behaves “linearly” on some inputs and completely differently on others: that is the effect of a crease. Turn on ReLU in Lab E and see where ◆ lands.

为什么纯线性模型算不出 XORWhy no linear model can compute XOR

任何仿射函数都可以写成 f(x₁, x₂) = a·x₁ + c·x₂ + e（a、c、e 是某三个数）。计算两组和：f(0,0) + f(1,1) = e + (a + c + e) = a + c + 2e；f(1,0) + f(0,1) = (a + e) + (c + e) = a + c + 2e。两者永远相等。但 XOR 要求前者是 0 + 0 = 0，后者是 1 + 1 = 2。矛盾。所以不论多少个纯线性层（它们合起来仍是一个仿射函数），都不可能把四个输入全部算对。而实验 D 中 ReLU 的折痕打破了这个等式。

Any affine function can be written f(x₁, x₂) = a·x₁ + c·x₂ + e for some numbers a, c, e. Compute two sums: f(0,0) + f(1,1) = e + (a + c + e) = a + c + 2e, and f(1,0) + f(0,1) = (a + e) + (c + e) = a + c + 2e. They are always equal. XOR requires the first to be 0 + 0 = 0 and the second 1 + 1 = 2. Contradiction. So no stack of purely linear layers (which together is still one affine function) can get all four inputs right. In Lab D, ReLU's crease is what breaks this equality.

非线性带来了什么，没带来什么What nonlinearity buys, and what it does not

每个 ReLU 神经元都在输入空间中加一道折痕；足够多的折痕，就能把空间分成许多区域，每个区域内是不同的线性函数，从而逼近相当复杂的形状。经典的“万能逼近定理”（Cybenko 1989；Leshno 等 1993）说：只要隐藏层足够宽、激活函数不是多项式，一个隐藏层就能以任意精度逼近有界区域上的连续函数。它只说明这样的参数存在，不说明训练能找到它们，也不说明所需的规模是否现实。深度在效率上的优势有一些理论结果，但不是简单的一句话就能概括的，这里不做更强的断言。

Each ReLU neuron adds one crease to the input space; enough creases divide the space into many regions, each with a different linear function, which lets the network approximate quite complicated shapes. The classic universal approximation theorem (Cybenko 1989; Leshno et al. 1993) says that with a wide enough hidden layer and a non-polynomial activation, a single hidden layer can approximate any continuous function on a bounded region to any accuracy. It only says such parameters exist. It says nothing about whether training finds them or whether the required size is realistic. There are theoretical results on the efficiency advantages of depth, but they do not reduce to a single slogan, so we make no stronger claim here.

“合并”不等于“没用”“Collapsible” is not “useless”

两个线性层在功能上等于一个，但参数个数可以不同。例如 [4096, 8] 和 [8, 4096] 两个矩阵相乘得到一个 [4096, 4096] 的矩阵，却只需要 2×4096×8 = 65,536 个参数，而不是 16,777,216 个。这种“低秩分解”有实际用途（例如微调方法 LoRA）。在注意力中，每个头的 V 投影和输出投影之间也没有非线性。所以“两个矩阵直接相乘”在真实架构中并不罕见，只是它不增加表达能力。

Two linear layers equal one in function, but the parameter counts can differ. For example, multiplying a [4096, 8] matrix by an [8, 4096] matrix gives a [4096, 4096] matrix but needs only 2×4096×8 = 65,536 parameters instead of 16,777,216. This “low-rank factorisation” has real uses (for example the fine-tuning method LoRA). In attention, each head's value projection and output projection also have no nonlinearity between them. So “two matrices multiplied directly” is not rare in real architectures; it just adds no expressive power.

6与真实模型的联系Connection to real models

Transformer 每个块里的 MLP 子层（也叫前馈网络 FFN）就是本节的结构：先扩宽，过非线性，再投影回原宽度，对每个位置独立计算。GPT-2 small：768 → 3072（GELU）→ 768。参数为 768×3072 + 3072 + 3072×768 + 768 = 4,722,432 个；12 个块合计约 5,667 万，约占总参数 1.24 亿的 45%（按 GPT-2 配置自行计算）。

The MLP sublayer (also called the feed-forward network, FFN) in every Transformer block has exactly this section's structure: widen, apply a nonlinearity, project back to the original width, computed independently at each position. GPT-2 small: 768 → 3072 (GELU) → 768. That is 768×3072 + 3072 + 3072×768 + 768 = 4,722,432 parameters; across 12 blocks, about 56.67 million, roughly 45% of the 124 million total (our own arithmetic from the GPT-2 configuration).

现代变体A modern variation

Llama 2 7B 的 MLP 使用 SwiGLU（Shazeer 2020）：两个并行的 [4096 → 11008] 投影，其中一个经过 SiLU 后与另一个逐元素相乘（“门控”），再经 [11008 → 4096] 投影回来，且不使用偏置。每块 MLP 参数 3×4096×11008 = 135,266,304 个。原理仍是“线性—非线性—线性”，细节见选修专题 D2。模型中还有其他非线性来源：注意力中的 softmax（第 5.3 章）和归一化（第 4.4 章）。

Llama 2 7B's MLP uses SwiGLU (Shazeer 2020): two parallel [4096 → 11008] projections, one passed through SiLU and multiplied element-wise with the other (the “gate”), then a [11008 → 4096] projection back, with no biases. That is 3×4096×11008 = 135,266,304 MLP parameters per block. The principle is still “linear, nonlinear, linear”; details are in deep dive D2. Models contain other sources of nonlinearity too: softmax inside attention (Chapter 5.3) and normalization (Chapter 4.4).

Softmax：把任意分数变成权重Softmax: Turning Arbitrary Scores into Weights

≈ 12 min前置：2.2Prerequisites: 2.2

1问题The problem

模型经常先算出一组“分数”，它们可以是任意实数：正、负、很大、很小。点积就会产生这样的分数。之后有两处需要把分数变成“分配比例”：注意力要决定从每个位置取多少信息（第 5 部分）；输出层要给词表中每个 token 一个概率（第 6 部分）。比例必须非负、加起来等于 1，并且分数越高比例越大。直接除以总和行不通：负数会产生负比例，总和还可能是 0。

Models often compute a set of “scores” that can be any real numbers: positive, negative, large or small. Dot products produce exactly such scores. Two places then need to turn scores into proportions: attention must decide how much to take from each position (Part 5), and the output layer must give each vocabulary token a probability (Part 6). Proportions must be non-negative, add up to 1, and grow with the score. Simply dividing by the total fails: negative scores give negative proportions, and the total might be 0.

2直觉The intuition

两步走：先把每个分数变成一个正数，并且分数每高 1，正数就乘以同一个倍数（约 2.718 倍），这样分数之间的“差距”被保留并放大；再把这些正数除以它们的总和，让它们加起来等于 1。第一步用的是指数函数 ez，e ≈ 2.718。

Two steps. First turn each score into a positive number such that every extra point of score multiplies the number by the same factor (about 2.718), so differences between scores are preserved and amplified. Then divide those positive numbers by their total so they sum to 1. The first step uses the exponential function ez, with e ≈ 2.718.

This is why attention controls the scale of its scores (5.3).

6它不意味着什么What it does not imply

常见误读Common misreadings

(1) softmax 的输出加起来为 1，看起来像概率，但这只是数学形式。在输出层，它确实被训练成预测下一个 token 的概率分布；可是“模型给某个答案 0.9”并不等于“答案有 90% 的把握是对的”。模型的概率是否与真实正确率一致（称为校准），需要另外检验。(2) 在注意力中，softmax 给出的是混合比例，不是“模型认为哪个词重要”的解释（5.7）。(3) softmax 不做选择：它给每一项都分配非零份额，最大项也只是份额最大。

(1) Softmax outputs sum to 1 and look like probabilities, but that is only the mathematical form. At the output layer it is indeed trained to predict a distribution over the next token; yet “the model gives an answer 0.9” does not mean “the answer is 90% likely to be correct”. Whether a model's probabilities match real accuracy (calibration) must be checked separately. (2) In attention, softmax produces mixing proportions, not an explanation of what the model “considers important” (5.7). (3) Softmax does not select: it gives every entry a non-zero share; the largest entry just gets the largest share.

分词与 token ID：文本进入模型的第一步Tokenization and Token IDs: How Text Enters the Model

≈ 10 min前置：2.1Prerequisites: 2.1
关于这一章About this chapter

你已经知道“文本会被切成 token”。这一章不重复这句话，而是回答三个更具体的问题：为什么切成子词而不是词或字？ID 这个整数在后续计算里到底被怎样使用？为什么中文的 token 数往往和英文不同？

You already know that “text is split into tokens”. This chapter does not repeat that. It answers three more specific questions: why split into subwords rather than words or characters? How is the integer ID actually used in later computation? Why do Chinese and English often produce different token counts?

1问题The problem

模型需要一张有限的表：每个条目对应一行参数（4.2）。如果以“词”为单位，词是无穷的（新词、拼写错误、代码、人名），表永远不够；如果以“字符”或“字节”为单位，表很小，但序列会变得很长，而第 5、7 部分会看到，计算和显存都随序列长度增长。需要一个折中。

The model needs a finite table, each entry with one row of parameters (4.2). With words as units, the set is unbounded (new words, typos, code, names) and the table is never big enough. With characters or bytes, the table is tiny, but sequences become very long, and Parts 5 and 7 show that compute and memory grow with sequence length. We need a compromise.

2直觉The intuition

子词分词：常见的词作为一个整体（如“模型”），不常见的词拆成几个常见片段（如一个生僻的长词被拆成两三段常见的部分），极少见的内容退回到字节。片段表是从大量文本中统计出来的。最常见的方法是 BPE（字节对编码）：从单个字节出发，反复把语料中最常一起出现的相邻两块合并成新条目，直到词表达到预定大小。

Subword tokenization: common words stay whole (“ the”, “ model”), uncommon words split into common pieces (“token” + “ization”), and very rare content falls back to bytes. The piece table is learned statistically from a large corpus. The most common method is BPE (byte-pair encoding): start from single bytes and repeatedly merge the pair of adjacent pieces that occurs most often in the corpus into a new entry, until the vocabulary reaches a chosen size.

3实际对象The actual objects

分词器是一段独立于模型权重的程序加数据（词表与合并规则）。token ID 是一个整数，范围 0 到 V−1，V 是词表大小：GPT-2 为 50257，Llama 2 为 32000，Llama 3 为 128256。ID 在模型中只有一个用途：作为行号，到嵌入表中取出第 ID 行（4.2）。ID 的大小只反映它在词表构建时的位置，与含义无关：ID 相邻的两个 token 可以毫不相干，模型也从不对 ID 做加减乘除。

The tokenizer is a program plus data (vocabulary and merge rules), separate from the model weights. A token ID is an integer from 0 to V−1, where V is the vocabulary size: 50257 for GPT-2, 32000 for Llama 2, 128256 for Llama 3. Inside the model an ID has exactly one use: as a row number, to fetch row ID from the embedding table (4.2). Its size only reflects where the token landed when the vocabulary was built and says nothing about meaning; tokens with neighbouring IDs can be unrelated, and the model never adds or multiplies IDs.

还有特殊 token：如序列开始（BOS）、序列结束（EOS），以及对话模型用来标记“系统”“用户”“助手”轮次的标记。聊天 API 中你发出的消息，会先按模型的对话模板插入这些标记，再一起分词。

There are also special tokens: beginning of sequence (BOS), end of sequence (EOS), and markers chat models use for “system”, “user” and “assistant” turns. Messages you send through a chat API are first wrapped with these markers according to the model's chat template, then tokenized together.

4.2

嵌入查表：从 ID 到第一批向量Embedding Lookup: From IDs to the First Vectors

≈ 10 min前置：4.1、2.3Prerequisites: 4.1, 2.3

1问题The problem

分词器给出一串整数 ID，而第 1 部分说过，整数本身不能参与有意义的计算。我们需要把每个 ID 换成一个 d 维向量，并且这些向量应该是可学习的，让训练来决定每个 token 用什么向量表示。

The tokenizer outputs a list of integer IDs, and Part 1 showed that integers themselves cannot take part in meaningful computation. We need to replace each ID with a d-dimensional vector, and those vectors should be learnable, so that training decides what vector represents each token.

2直觉与实际对象Intuition and actual object

准备一张 V 行、d 列的表，第 k 行就是 ID 为 k 的 token 的向量。这张表叫嵌入矩阵 E，形状 [V, d]，它是参数。“嵌入查表”就是：对每个 ID，取出 E 的那一行。n 个 ID 得到形状 [n, d] 的矩阵 X₀，这是第一批激活值，从这里开始进入各个 Transformer 块。

Prepare a table with V rows and d columns; row k is the vector for the token with ID k. This table is the embedding matrix E, shape [V, d], and it is a parameter. “Embedding lookup” means: for each ID, take that row of E. n IDs give a matrix X₀ of shape [n, d], the first activations, which then enter the Transformer blocks.

查表与矩阵乘法的关系：把 ID k 写成一个长度为 V 的 独热向量（第 k 个位置是 1，其余全是 0），它乘以 E，结果正好是 E 的第 k 行，因为其余各行都被乘以 0。所以嵌入层在数学上就是“一个输入为独热的线性层”；实际实现直接按行号读取，省掉了与大量 0 相乘。

Lookup and matrix multiplication: write ID k as a length-V one-hot vector (1 at position k, 0 elsewhere). Multiply it by E and the result is exactly row k of E, because every other row is multiplied by 0. So mathematically the embedding layer is “a linear layer whose input is one-hot”; implementations simply read the row by index and skip multiplying by all those zeros.

Note also that although the whole table sits in memory, each token reads only one row, so the embedding table contributes storage but almost no compute.

4.3

位置信息：为什么模型需要知道“第几个”Positional Information: Why the Model Needs to Know “Which Position”

≈ 10 min前置：4.2Prerequisites: 4.2

1问题The problem

“狗咬人”和“人咬狗”由同样的 token 组成。4.2 的初始嵌入只取决于 token 本身，与位置无关。第 5 部分的注意力会让每个位置按“相似度”从其他位置汇集信息，而相似度只看向量内容；如果向量里没有位置信息，把输入顺序打乱，每个 token 得到的结果只会跟着换位置，数值本身不变。模型将无法区分这两个句子。

“Dog bites man” and “man bites dog” contain the same tokens. The initial embeddings from 4.2 depend only on the token, not its position. Attention in Part 5 lets each position gather information from others according to similarity, and similarity only looks at vector contents; without positional information, shuffling the input would merely shuffle each token's result, leaving the values unchanged. The model could not tell the two sentences apart.

2两种主流做法Two mainstream approaches

(a) 学习的绝对位置嵌入（GPT-2）：再准备一张表 P，形状 [最大位置数, d]，GPT-2 为 [1024, 768]。第 i 个位置的输入变成 X₀[i] = E[IDi] + P[i]。P 是参数，训练时学到。直接后果：超过 1024 的位置在表里没有对应行，所以 GPT-2 无法处理更长的输入。

(a) Learned absolute position embeddings (GPT-2): a second table P of shape [max positions, d], [1024, 768] in GPT-2. The input at position i becomes X₀[i] = E[IDi] + P[i]. P is a parameter learned in training. A direct consequence: positions beyond 1024 have no row in the table, so GPT-2 cannot process longer inputs.

(b) 旋转位置编码 RoPE（Llama 等，Su 等 2021）：不在输入上加任何东西，而是在注意力内部，把 Q 和 K 向量的每两个分量看成平面上的一个箭头，按位置转一个角度：位置 m 转 m·θ。两个箭头转过之后再做点积，结果只取决于它们的角度差，也就是 (m − n)·θ。于是注意力分数自然地依赖相对位置。不同的分量对使用不同的 θ（有的转得快，有的转得慢），以覆盖不同的距离尺度。RoPE 没有可学习参数。

(b) Rotary position embedding, RoPE (Llama and others; Su et al., 2021): nothing is added to the input. Instead, inside attention, each pair of components of the Q and K vectors is treated as an arrow in a plane and rotated by an angle that depends on position: position m rotates by m·θ. When two rotated arrows are then dotted, the result depends only on their angle difference, (m − n)·θ. Attention scores thus depend naturally on relative position. Different component pairs use different θ (some rotate fast, some slowly) to cover different distance scales. RoPE has no learned parameters.

GPT-2 uses learned absolute position embeddings; Llama 2/3, Mistral, Qwen and others use RoPE. A config's max_position_embeddings (4096 for Llama 2) gives the length set for training. 4.4

残差连接与归一化：深层网络的两根支柱Residual Connections and Normalization: Two Pillars of Deep Networks

≈ 12 min前置：4.2、3.4Prerequisites: 4.2, 3.4

1问题The problem

如果每一层都把输入整个改写成新向量（h = f(x)），那么堆叠几十层后有两个麻烦：早期的信息（例如原始 token 是什么）很容易在层层改写中丢失；训练时，误差信号要从最后一层一路传回第一层，经过几十次变换后容易变得极小或极大（第 6 部分）。另一个问题是数值尺度：向量的长度若在层间不断变大或变小，点积和 softmax 会变得极端（2.2、2.5）。

If every layer completely rewrites its input into a new vector (h = f(x)), stacking dozens of layers causes two problems: early information (such as which token was originally there) is easily lost through repeated rewriting; and in training, the error signal must travel from the last layer back to the first, and after dozens of transformations it tends to become tiny or huge (Part 6). A separate problem is scale: if vector lengths keep growing or shrinking from layer to layer, dot products and softmax become extreme (2.2, 2.5).

2直觉The intuition

残差连接：每个子层不改写向量，而是计算一个增量，加回原向量上：x ← x + f(x)。可以把每个位置的向量想成一块共享的“黑板”，称为残差流：每个子层读黑板、算出要补充的内容、写回去（加上去），原来的内容仍在，除非后续增量把它抵消。归一化：子层读黑板之前，先把读到的向量调整到标准尺度，避免数值失控。

Residual connection: instead of rewriting the vector, each sublayer computes an update and adds it back: x ← x + f(x). Think of each position's vector as a shared blackboard, the residual stream: each sublayer reads the board, computes what to add, and writes it back (by adding). The previous contents remain unless later updates cancel them. Normalization: before a sublayer reads the board, the vector it reads is rescaled to a standard size, keeping numbers under control.

Interpretability research often views a model as “many sublayers reading from and writing to one residual stream”, one reason why “layer N is responsible for X” is unreliable (3.3): information can be read by any later layer.

从初始嵌入到上下文表示From Initial Embeddings to Contextual Representations

≈ 8 min前置：4.4Prerequisites: 4.4

1问题The problem

“我吃了一个苹果”和“苹果发布了新手机”中的“苹果”是同一个 token，因此在 4.2 中得到同一行嵌入。但要预测后面的词，模型必须知道这里的“苹果”是水果还是公司。初始嵌入做不到这一点，因为它只看 token 本身。

In “I ate an apple” and “Apple released a new phone”, “apple” is the same token (in a case-insensitive toy), so in 4.2 it gets the same embedding row. To predict what comes next, the model must know whether this “apple” is a fruit or a company. The initial embedding cannot do that, because it looks only at the token itself.

We know the MLP computes each position independently and brings in nothing from other positions. So how exactly is “gathering information from other positions” done? Which positions, and how much from each, must be decided by the data rather than fixed in advance. That is the problem attention solves.

第 5 部分 · 5.1Part 5 · 5.1

注意力要解决的问题：从可见上下文中按需汇集信息The Problem Attention Solves: Gathering Information from the Visible Context, as Needed

≈ 8 min前置：4.5、2.5Prerequisites: 4.5, 2.5

1问题The problem

考虑“小明把书递给了小红，因为她需要它”。要处理“她”这个位置，模型需要“小红”位置上的信息；而在“小明把书递给了小红，因为他想帮忙”中，需要的是“小明”。需要哪个位置、需要多少，取决于内容，而且距离可近可远。MLP 只看本位置（4.5）；如果用固定规则，例如“总是取前 3 个位置的平均”，就无法适应这些变化。

Consider “Alex handed the book to Sam because she needed it.” To process the position of “she”, the model needs information from the position of “Sam”; in “Alex handed the book to Sam because he wanted to help”, it needs “Alex”. Which positions are needed, and how much, depends on content, and the distance may be short or long. The MLP looks only at its own position (4.5); a fixed rule such as “always average the previous 3 positions” cannot adapt to this.

2直觉The intuition

让每个位置做三件事：(1) 根据自己当前的向量，产生一个“我在找什么样的信息”的描述；(2) 每个可见位置也产生一个“我能提供什么样的信息”的描述，以及一份“如果被选中，我交出的内容”；(3) 用点积比较“在找的”和“能提供的”，得到相关性分数，再用 softmax 变成比例，按比例把各位置交出的内容加权混合，作为本位置的增量。这三份描述分别叫查询、键和值。

Let each position do three things: (1) from its current vector, produce a description of “what kind of information I am looking for”; (2) every visible position likewise produces a description of “what kind of information I can offer”, plus “what I hand over if chosen”; (3) compare “looking for” with “can offer” by dot product to get relevance scores, turn them into proportions with softmax, and mix the handed-over contents in those proportions to form this position's update. The three descriptions are called Query, Key and Value.

类比与边界：常有人把它比作图书馆检索：查询是检索词，键是书目标签，值是书的内容。这个类比在“用相似度决定取多少”这一点上有帮助，但有三处误导：(1) Q、K、V 不是文字，而是向量，由学到的矩阵从同一个隐藏状态算出（5.2）；(2) 结果不是“取回一本书”，而是所有可见位置内容的加权混合（5.4）；(3) 没有人规定 Q 和 K 要表达什么，它们的“含义”完全由训练决定，常常无法用语言描述。

Analogy and its limits: attention is often compared with library search: the query is a search term, keys are catalogue labels, values are book contents. That helps with the idea that similarity decides how much to take, but misleads in three ways: (1) Q, K and V are not text but vectors, computed by learned matrices from the same hidden state (5.2); (2) the result is not “retrieving one book” but a weighted mixture of all visible positions' contents (5.4); (3) nobody specifies what Q and K should express; their “meaning” is set entirely by training and often has no verbal description.

3注意力在整个模型中的位置Where attention sits in the whole model

在每个 Transformer 块中，注意力子层是唯一让信息在位置之间流动的地方。其余部分（归一化、MLP、残差相加）都对每个位置独立计算。所以，如果你想知道“前文的信息是怎么到达当前位置的”，答案一定经过注意力。本部分将依次讲：如何得到 Q、K、V（5.2）；如何算分数、缩放、遮住未来、做 softmax（5.3）；如何加权组合 V（5.4）；为什么要多个头（5.5）；以及它如何和 MLP 组成完整的块（5.6）。

In every Transformer block, the attention sublayer is the only place where information moves between positions. Everything else (normalization, MLP, residual addition) works on each position independently. So if you want to know how information from earlier text reaches the current position, the answer always goes through attention. This part covers, in order: how Q, K and V are obtained (5.2); how scores are computed, scaled, masked and softmaxed (5.3); how V is combined (5.4); why there are several heads (5.5); and how attention and the MLP form a complete block (5.6).

5.2

Q、K、V：同一个输入，三个学到的投影Q, K, V: One Input, Three Learned Projections

≈ 14 min前置：5.1、3.2Prerequisites: 5.1, 3.2

1问题The problem

一个位置的隐藏状态需要同时扮演三种角色：去找别人（查询）、被别人找（键）、被找到后交出内容（值）。如果直接用同一个向量扮演三种角色，那么“A 有多想要 B”就等于“B 有多想要 A”（点积对称），而且交出的内容和用于匹配的特征必须完全相同。这太受限了。

A position's hidden state must play three roles at once: looking for others (query), being looked for (key), and handing over content once found (value). If one vector played all three roles, “how much A wants B” would equal “how much B wants A” (the dot product is symmetric), and the content handed over would have to be identical to the features used for matching. That is far too restrictive.

2实际对象The actual object

解决办法是用三个不同的参数矩阵，把同一个输入投影成三个不同的向量。这就是 3.2 的线性层，只是没有激活函数：

The fix is three different parameter matrices that project the same input into three different vectors. Each is just a linear layer from 3.2, without an activation:

Q = X WQ    K = X WK    V = X WV
X [n, dmodel]
归一化后的残差流（每行一个位置）。激活值。The normalized residual stream (one row per position). Activations.
WQ, WK, WV [dmodel, dk]
三个参数矩阵，所有位置共享。dk 是每个头的维度（5.5）。Three parameter matrices shared by all positions. dk is the per-head dimension (5.5).
Q, K, V [n, dk]
每个位置一个查询、一个键、一个值。激活值，每次输入都重新计算。One query, one key and one value per position. Activations, recomputed for every input.

关键点：Q、K、V 是激活值，WQ、WK、WV 是参数。训练调整的是三个矩阵；三个矩阵决定了“什么样的隐藏状态会去找什么样的隐藏状态”。因为 WQ ≠ WK，A 对 B 的分数 qA·kB 一般不等于 B 对 A 的分数 qB·kA。

Key point: Q, K and V are activations; WQ, WK and WV are parameters. Training adjusts the three matrices, and they determine “which kinds of hidden state look for which kinds”. Because WQ ≠ WK, A's score for B, qA·kB, generally differs from B's score for A, qB·kA.

分数、缩放、因果掩码与 softmaxScores, Scaling, the Causal Mask and Softmax

≈ 16 min前置：5.2、2.5Prerequisites: 5.2, 2.5

1问题The problem

有了每个位置的 q 和 k，还需要回答：位置 i 应该从位置 j 取多少？这需要四步：比较（得分）、控制分数的尺度（缩放）、禁止看到未来（掩码）、把分数变成比例。每一步都有具体的理由。

With a q and a k for every position, we still need to answer: how much should position i take from position j? That takes four steps: compare (scores), control the scale of the scores (scaling), forbid looking at the future (masking), and turn scores into proportions (softmax). Each step has a concrete reason.

2实际对象：四步公式The actual object: the four steps as a formula

A = softmax( Q Kᵀ / √dk + M )    [n, n]
Q Kᵀ
分数矩阵 [n, n]。Kᵀ 是 K 的转置（行列互换，[dk, n]），所以 Q Kᵀ 的第 i 行第 j 列就是 qi·kj：位置 i 的查询与位置 j 的键的点积。一次矩阵乘法算出所有位置对的分数。The score matrix [n, n]. Kᵀ is K transposed (rows and columns swapped, [dk, n]), so entry (i, j) of Q Kᵀ is qi·kj: position i's query dotted with position j's key. One matrix multiplication computes scores for every pair of positions.
/ √dk
缩放。dk 个分量的点积，若各分量是均值 0、方差 1 的随机数，其标准差约为 √dk。dk = 128 时分数动辄几十，softmax 会极端地集中在一项上（2.5 的“对缩放敏感”），训练时梯度也会几乎消失。除以 √dk 把分数拉回到大约单位尺度。Scaling. If the dk components were random with mean 0 and variance 1, their dot product would have standard deviation about √dk. With dk = 128, scores easily reach tens, softmax collapses onto a single entry (the scale sensitivity of 2.5), and gradients nearly vanish during training. Dividing by √dk brings scores back to roughly unit scale.
M
因果掩码 [n, n]：j ≤ i 的位置为 0，j > i 的位置为 −∞。加上 −∞ 后 e−∞ = 0，未来位置的权重恰好为 0。它不是参数，是固定的规则。The causal mask [n, n]: 0 where j ≤ i, −∞ where j > i. After adding −∞, e−∞ = 0, so future positions get exactly zero weight. It is a fixed rule, not a parameter.
softmax
对每一行分别做 softmax：第 i 行变成位置 i 分配给各位置的比例，和为 1。Applied to each row separately: row i becomes the proportions position i assigns to every position, summing to 1.
A
注意力权重 [n, n]，激活值。The attention weights [n, n], activations.

为什么要遮住未来？语言模型被训练成“根据前文预测下一个 token”。训练时整段文本同时输入（6.5），如果位置 i 能看到位置 i+1，它就能直接“抄答案”，学不到任何预测能力；而生成时未来的 token 根本还不存在。因果掩码让训练与生成的条件一致：每个位置只能看到自己和之前的位置。

Why hide the future? A language model is trained to predict the next token from what came before. In training the whole text is fed in at once (6.5); if position i could see position i+1 it could simply copy the answer and learn nothing about prediction, and in generation the future tokens do not exist yet. The causal mask keeps training and generation consistent: each position sees only itself and earlier positions.

5.4

用权重组合 V：结果是混合，而不是选择Weighting V: The Result Is a Mixture, Not a Selection

≈ 10 min前置：5.3Prerequisites: 5.3

1问题与实际对象The problem and the actual object

权重 A 只说明“各取多少”，还没有真正把信息取过来。最后一步把每一行的权重用在 V 上：

The weights A only say how much to take from each position; nothing has been taken yet. The last step applies each row of weights to V:

O = A V    oi = Σj Ai,j vj    [n, n] × [n, dk] → [n, dk]

oi 是一个新向量：所有可见位置的值向量，按权重加权平均。它通常不等于任何一个 vj。即使某个权重是 0.9，结果里仍有 10% 来自其他位置。所以说“注意力选中了某个词”并不准确：它产生的是混合。只有当一个权重接近 1、其余接近 0 时，结果才接近“复制”那个位置的值。

oi is a new vector: a weighted average of all visible positions' value vectors. It usually equals none of the vj. Even with one weight at 0.9, 10% of the result comes from elsewhere. So “attention selected a word” is inaccurate; it produces a mixture. Only when one weight is near 1 and the rest near 0 does the result approach copying that position's value.

2最小数值例子A minimal numerical example

延续 5.3：位置 3 的权重 ≈ (0.248, 0.503, 0.248, 0)，值向量 v₁ = (1, −1)、v₂ = (1, 3)、v₃ = (1, 1)。o₃ = 0.248×(1, −1) + 0.503×(1, 3) + 0.248×(1, 1) ≈ (1.00, 1.51)。它不是 v₁、v₂、v₃ 中任何一个，而是偏向 v₂ 的混合。实验 5.3 的第 7 步显示了所有位置的结果。

Continuing 5.3: position 3's weights are ≈ (0.248, 0.503, 0.248, 0) and the values are v₁ = (1, −1), v₂ = (1, 3), v₃ = (1, 1). o₃ = 0.248×(1, −1) + 0.503×(1, 3) + 0.248×(1, 1) ≈ (1.00, 1.51). It is none of v₁, v₂, v₃, but a mixture leaning towards v₂. Step 7 of Lab 5.3 shows the result for every position.

3与真实模型的联系Connection to real models

oi 的形状是 [dk]（例如 128），比残差流的 dmodel（例如 4096）小得多。它还不能直接加回残差流：多个头的结果先拼接，再经过一个输出投影 WO 变回 dmodel（5.5）。另外要注意：一个位置得到的“信息量”不只取决于权重，还取决于值向量本身的大小。权重很高但值向量很小，贡献也可能很小。这是 5.7 中“注意力图不等于解释”的原因之一。

oi has shape [dk] (e.g. 128), much smaller than the residual stream's dmodel (e.g. 4096). It cannot be added back directly: the results of several heads are concatenated and passed through an output projection WO back to dmodel (5.5). Also note that how much information a position contributes depends not only on its weight but on the size of its value vector; a high weight on a small value can contribute little. That is one reason, in 5.7, why attention maps are not explanations.

5.5

多头注意力：并行的多组 Q、K、VMulti-Head Attention: Several Sets of Q, K, V in Parallel

≈ 14 min前置：5.4Prerequisites: 5.4

1问题The problem

一个头的每一行只有一组权重。但一个位置可能同时需要几种不同的信息，例如来自前一个 token 的信息和来自远处某个相关名词的信息。一组 softmax 权重只能给出一种混合方式；想同时取两种，就会互相稀释。

Each row of one head has a single set of weights. But a position may need several different kinds of information at once, say from the previous token and from a related noun far back. One set of softmax weights gives one mixture; trying to take both at once dilutes each.

2实际对象The actual object

使用 h 个头，每个头有自己的 WQ(h)、WK(h)、WV(h)，形状都是 [dmodel, dhead]，通常 dhead = dmodel / h。每个头独立完成 5.2–5.4 的全部计算，得到自己的 [n, dhead] 输出。然后：

Use h heads, each with its own WQ(h), WK(h), WV(h) of shape [dmodel, dhead], usually with dhead = dmodel / h. Each head independently runs all of 5.2–5.4 and yields its own [n, dhead] output. Then:

MultiHead(X) = Concat(O(1), …, O(h)) WO    [n, h·dhead] × [dmodel, dmodel] → [n, dmodel]

拼接把 h 个 [n, dhead] 并排放在一起，得到 [n, dmodel]；输出投影 WO（参数）再把各头的结果混合起来，并为加回残差流准备好形状。实现上，所有头的 WQ 被存成一个 [dmodel, dmodel] 的大矩阵，一次乘法后把结果“重排”成 [h, n, dhead]，所以多头并不比单头多做矩阵乘法，参数量也相同：只是把同样的维度切成了 h 份分别做 softmax。

Concatenation places the h outputs of [n, dhead] side by side, giving [n, dmodel]; the output projection WO (a parameter) then mixes the heads' results and produces the right shape for adding back to the residual stream. In implementations, all heads' WQ are stored as one [dmodel, dmodel] matrix; one multiplication is followed by reshaping into [h, n, dhead]. So multi-head attention does no more matrix multiplication than a single wide head and has the same parameter count; it just splits the same dimensions into h groups, each with its own softmax.

研究确实发现了一些行为清晰的头，例如总是关注前一个 token 的头，以及能完成“看到 A B … A 就预测 B”的“归纳头”（Olsson 等，2022）。但这些是在特定模型中通过分析找到的，并非设计出来的；许多头没有简单的描述；不同训练运行中同一编号的头毫无对应关系；还有研究发现，删除大量头对性能影响很小（Michel 等，2019）。所以“第 5 层第 3 个头负责语法”这类说法，除非有针对该模型的证据，否则不成立。

Research has found some heads with clear behaviour, such as heads that always attend to the previous token, and “induction heads” that complete patterns like “A B … A → predict B” (Olsson et al., 2022). But these were found by analysing specific models, not designed; many heads have no simple description; heads with the same index in different training runs have nothing to do with each other; and studies have found that removing many heads barely affects performance (Michel et al., 2019). So claims like “layer 5, head 3 handles grammar” do not hold without evidence for that specific model.

The two sublayers have different jobs. Attention moves and mixes information between positions (the only place that does so). The MLP applies a nonlinear transformation to each position separately and usually holds about two-thirds of the block's parameters (GPT-2: 4.72M vs 2.36M). A common but cautious reading is “attention routes information between positions; the MLP does per-position processing (some research argues it stores many factual associations, e.g. Geva et al. 2021; Meng et al. 2022)”. The first half is a structural fact; the second half is a research interpretation, not settled.

Attention heatmaps are intuitive, but using them to explain “why the model answered this way” calls for great care: (1) they show the mixing proportions of one head in one layer, while a model has dozens of layers with dozens of heads each; (2) the contribution also depends on value-vector size and WO (5.4), so high weight does not mean high contribution; (3) the mixed information passes through later MLPs and many more layers, so the link between one map and the final output is very indirect; (4) studies show that in some settings very different attention distributions can produce nearly identical predictions (Jain & Wallace 2019; see also the discussion by Wiegreffe & Pinter 2019). Probing: train a small classifier on one layer's activations to see whether some information can be read out. Limit: being readable does not mean the model uses it. Intervention / causal tracing: modify activations at a position or layer and observe how the output changes (e.g. Meng et al. 2022). This gives causal evidence, but conclusions depend on how the intervention is done. Sparse autoencoders (SAEs): learn to decompose activations into many sparse “feature directions”, some of which humans can interpret (Bricken et al. 2023; Templeton et al. 2024). Limits: the decomposition is not unique, many features remain hard to interpret, and coverage is incomplete. These methods answer different questions; none currently gives a complete explanation of model behaviour.

2为什么用 −log pWhy −log p

我们需要一个数衡量“预测有多差”，并且：正确 token 的概率为 1 时等于 0；概率越小，惩罚越大；概率接近 0 时惩罚极大。−log p 恰好满足：p = 1 → 0；p = 0.5 → 0.69；p = 0.01 → 4.6。这叫交叉熵损失。注意它只看目标 token 的概率；其他 token 的概率通过 softmax 间接受影响（目标的概率要升高，其他就必须降低）。一个批次的损失是所有位置的平均值。

We need a number for “how bad the prediction is” that equals 0 when the correct token has probability 1, grows as that probability shrinks, and becomes very large near 0. −log p does exactly this: p = 1 → 0; p = 0.5 → 0.69; p = 0.01 → 4.6. This is the cross-entropy loss. It looks only at the target token's probability; other tokens are affected indirectly through softmax (for the target to rise, others must fall). 6.3

梯度、反向传播与优化器：参数到底怎样被改变Gradients, Backpropagation and Optimizers: How Parameters Actually Change

≈ 16 min前置：6.2、3.3Prerequisites: 6.2, 3.3

1问题The problem

我们有一个损失值，还有几十亿个参数。每个参数应该往哪个方向改、改多少，才能让损失下降？逐个试探（把一个参数加一点，重新计算整个模型）需要几十亿次前向计算，不可行。

We have one loss value and billions of parameters. Which way, and how much, should each parameter change to lower the loss? Trying each one in turn (nudge one parameter, rerun the whole model) would need billions of forward passes; it is infeasible.

2直觉The intuition

梯度是每个参数的“敏感度”：如果把这个参数增加一点点，损失会增加多少（正）或减少多少（负）。只要知道每个参数的梯度，就把每个参数往梯度的反方向挪一小步，损失就会下降（在步子足够小时）。反向传播是一次性算出所有梯度的方法：从损失出发，沿着前向计算的路径反过来，用链式法则逐层传递“敏感度”。它的计算量大约是一次前向计算的两倍，而不是几十亿倍。

A gradient is each parameter's sensitivity: if this parameter increased slightly, how much would the loss rise (positive) or fall (negative)? Knowing every parameter's gradient, move each one a small step against its gradient, and the loss falls (if the step is small enough). Backpropagation computes all gradients in one go: start from the loss and walk the forward computation backwards, passing sensitivities layer by layer with the chain rule. It costs roughly twice a forward pass, not billions of times.

6与真实训练的联系Connection to real training

真实训练与这个例子的区别：(1) 梯度是一个批次中成百万个位置的平均，单个例子的影响很小；(2) 学习率通常很小（例如 10⁻⁴ 量级），一次更新只让参数微动；(3) 反向传播需要用到前向计算时的中间激活值，所以训练要把它们保存下来，这是训练比推理更耗显存的主要原因之一；(4) 优化器通常不是上面的简单规则（SGD），而是 AdamW 等，它为每个参数保存额外的统计量（D5）。

How real training differs: (1) the gradient averages over millions of positions in a batch, so any single example has a tiny effect; (2) the learning rate is usually small (around 10⁻⁴), so each update nudges parameters only slightly; (3) backpropagation needs the forward pass's intermediate activations, so training must keep them, a main reason training uses far more memory than inference; (4) the optimizer is usually not the simple rule above (SGD) but something like AdamW, which stores extra statistics per parameter (D5).

深入 D5（可选，约 12 分钟）：Adam 与训练显存Deeper D5 (optional, about 12 min): Adam and training memory

Adam（Kingma & Ba 2014）为每个参数维护两个滑动平均：梯度的平均 m（给更新一个稳定的方向）和梯度平方的平均 v（按每个参数的典型梯度大小调整步长）。更新近似为 W ← W − η · m / (√v + ε)。AdamW 另外加入权重衰减。

Adam (Kingma & Ba 2014) keeps two running averages per parameter: the mean gradient m (a steadier direction) and the mean squared gradient v (scaling each parameter's step by its typical gradient size). The update is roughly W ← W − η · m / (√v + ε). AdamW adds weight decay.

一种常见的混合精度设置下，每个参数需要：BF16 权重 2 字节 + BF16 梯度 2 字节 + FP32 主权重 4 字节 + FP32 的 m 和 v 共 8 字节 = 约 16 字节（ZeRO 论文的估算，Rajbhandari 等 2020）。7B 模型仅这一项约 112 GB，还未计入激活值。相比之下，BF16 推理只需每个参数 2 字节。这就是“能在一张卡上跑推理”与“能训练”差距巨大的原因，也是 LoRA 等只训练少量参数的方法受欢迎的原因。具体数字随框架和设置而变。

In a common mixed-precision setup each parameter needs: BF16 weights 2 bytes + BF16 gradients 2 bytes + FP32 master weights 4 bytes + FP32 m and v 8 bytes = about 16 bytes (the ZeRO paper's estimate, Rajbhandari et al. 2020). For a 7B model that is about 112 GB before any activations. BF16 inference needs only 2 bytes per parameter. That is why “runs inference on one GPU” and “can be trained” are so far apart, and why methods such as LoRA that train only a few parameters are popular. Exact figures vary by framework and settings.

6.5

训练可以并行，生成必须逐个Training Runs in Parallel; Generation Must Go One Token at a Time

≈ 7 min前置：6.1、5.3Prerequisites: 6.1, 5.3

训练时，整段文本事先已知。把它一次性送进模型，因果掩码保证每个位置只看到前文，于是一次前向计算就同时得到所有 n 个位置的预测，它们与 n 个目标比较，得到损失。这种做法叫“教师强制”：每个位置的输入都是真实文本，而不是模型自己之前的预测。

In training the whole text is known in advance. Feed it in at once; the causal mask ensures each position sees only what came before, so one forward pass yields predictions for all n positions at the same time, which are compared with the n targets to get the loss. This is called teacher forcing: every position's input is the real text, not the model's own earlier predictions.

生成时，第 t+1 个 token 在第 t 步采样之前根本不存在，所以必须先算出它，追加到输入，才能计算下一个。每生成一个 token 都要一次（至少处理一个新位置的）前向计算。这是延迟的根本来源，也是第 7 部分 KV 缓存要解决的问题。

In generation, token t+1 does not exist until step t has sampled it, so it must be computed and appended before the next one can be. Every generated token needs one forward pass (processing at least one new position). This is the basic source of latency, and the problem the KV cache in Part 7 addresses.

6.6

从 logits 到一个 token：温度、top-k、top-pFrom Logits to One Token: Temperature, Top-k, Top-p

≈ 12 min前置：6.2Prerequisites: 6.2

1问题The problem

生成时，最后一个位置的 logits 经 softmax 给出下一个 token 的分布。必须从中选出一个。总是选概率最大的（贪心解码）简单且确定，但往往重复、单调；完全按分布随机抽样更多样，但偶尔会抽到概率很低的离谱 token。采样设置就是在这两者之间调节。

During generation, the last position's logits pass through softmax to give a distribution over the next token, and one token must be chosen. Always taking the most likely (greedy decoding) is simple and deterministic but tends to be repetitive and flat; sampling straight from the distribution is more varied but occasionally picks an absurd low-probability token. Sampling settings adjust between the two.

2三个设置The three settings

温度 T：softmax 前把 logits 除以 T（2.5）。T < 1 让分布更集中，T > 1 更平坦，T → 0 等同于贪心。top-k：只保留概率最高的 k 个 token，其余设为 0，再重新归一化。top-p（核采样）：按概率从高到低累加，保留使累计概率首次达到 p 的最小集合，再重新归一化；分布集中时保留的少，分散时保留的多。最后按处理后的分布随机抽一个。不同推理引擎执行这些步骤的顺序和细节可能略有不同（常见顺序是温度 → top-k → top-p），请查阅所用引擎的文档。

Temperature T: divide the logits by T before softmax (2.5). T < 1 concentrates the distribution, T > 1 flattens it, T → 0 is greedy. Top-k: keep only the k most likely tokens, zero the rest, renormalize. Top-p (nucleus sampling): add probabilities from highest to lowest and keep the smallest set whose total first reaches p, then renormalize; it keeps few tokens when the distribution is peaked and more when it is spread out. Finally draw one token at random from the processed distribution. Inference engines may apply these in slightly different orders and ways (a common order is temperature → top-k → top-p); check your engine's documentation.

要点Key point

采样设置只改变“如何从模型给出的分布中选”，不改变模型本身，也不改变 logits 的计算。同样的模型、同样的输入，在 T > 0 时每次运行都可能得到不同输出，这是随机抽样的结果，不是模型“改变了主意”。

Sampling settings only change how a token is chosen from the model's distribution; they change neither the model nor how logits are computed. With the same model and input, runs at T > 0 can differ because of random sampling, not because the model “changed its mind”.

6.7

生成循环、停止条件，以及为什么对话不改变权重The Generation Loop, Stopping, and Why Conversation Does Not Change Weights

≈ 7 min前置：6.6、6.5Prerequisites: 6.6, 6.5

循环：(1) 对当前上下文做前向计算，取最后一个位置的 logits；(2) 按采样设置选出一个 token；(3) 把它追加到上下文末尾，并（流式输出时）解码成文字发给用户；(4) 回到 (1)。停止条件：采到结束 token（EOS 或对话模板中的“轮次结束”标记）；生成内容匹配用户指定的停止序列；达到 max_tokens 上限；或上下文达到模型长度上限。

The loop: (1) run a forward pass over the current context and take the last position's logits; (2) choose a token according to the sampling settings; (3) append it to the context and (when streaming) decode it into text for the user; (4) go back to (1). Stopping conditions: the end token is sampled (EOS or the chat template's end-of-turn marker); the output matches a user-specified stop sequence; the max_tokens limit is reached; or the context hits the model's length limit.

为什么对话不改变权重：在整个循环中，参数只被读取（6.3 的更新步骤根本没有运行）。模型之所以能“记住”你几轮前说的话，是因为那些话作为 token 仍在上下文里，每次都被重新处理（或保存在 KV 缓存中，7.3）。所谓“上下文学习”（在提示里给几个例子，模型就照着做）完全发生在激活值层面。对话结束、上下文被丢弃后，这些“记忆”就没有了。一些产品提供的“记忆”功能，通常是把保存下来的文字在以后重新放进上下文，而不是更新权重。

Why conversation does not change weights: throughout the loop, parameters are only read (the update step of 6.3 never runs). The model “remembers” what you said several turns ago because those words are still in the context as tokens and are processed again each time (or kept in the KV cache, 7.3). So-called in-context learning (give a few examples in the prompt and the model follows them) happens entirely at the level of activations. When the conversation ends and the context is discarded, these “memories” are gone. “Memory” features in some products usually store text and put it back into the context later, rather than updating weights.

CPU、GPU、内存与数据搬运CPU, GPU, Memory and Data Movement

≈ 12 min前置：2.3、1.3Prerequisites: 2.3, 1.3

1问题The problem

前面几部分说明，模型的计算几乎全是矩阵乘法，而每生成一个 token 都要用到全部参数。于是有两个硬件问题：(1) 谁能最快地做海量乘加？(2) 几十 GB 的参数放在哪里，多快能读出来？很多人只关心第一个问题，但对于逐个生成 token 来说，第二个往往才是瓶颈。

The earlier parts showed that a model's computation is almost entirely matrix multiplication, and that every generated token uses all the parameters. That raises two hardware questions: (1) what can perform enormous numbers of multiply-adds fastest? (2) where do tens of gigabytes of parameters live, and how fast can they be read? Many people focus on the first, but for generating tokens one at a time, the second is often the bottleneck.

为什么 GPU 适合：矩阵乘法中，每个输出元素的点积互相独立（2.3），可以同时计算，正好匹配 GPU 的大规模并行。为什么数据搬运重要：计算单元每做一次乘加，都需要先把对应的数从显存读进来。如果读数据的速度跟不上计算的速度，计算单元就只能等待。

Why GPUs fit: in a matrix multiplication each output element's dot product is independent (2.3), so all can be computed at once, matching the GPU's massive parallelism. Why data movement matters: before each multiply-add, the numbers must be read from memory. If reading cannot keep up with computing, the compute units sit idle.

3关键计算：生成一个 token 时，谁是瓶颈？The key calculation: what is the bottleneck when generating one token?

只服务一个请求时，生成每个 token 都要把所有权重从显存读一遍（每个权重乘一次、加一次）。以 Llama 2 7B（BF16，约 13.5 GB）在 A100 80GB（标称带宽约 2.0 TB/s，BF16 稠密算力约 312 TFLOPS）上为例：读权重至少需要 13.5 GB ÷ 2.0 TB/s ≈ 6.7 ms，即每秒最多约 148 个 token；计算需要约 1.35×10¹⁰ 次浮点运算 ÷ 312×10¹² ≈ 0.04 ms。读数据比计算慢一百多倍。这种情况叫访存受限。

Serving a single request, every generated token requires reading all weights from memory once (each weight is used for one multiply and one add). Take Llama 2 7B (BF16, about 13.5 GB) on an A100 80GB (nominal bandwidth about 2.0 TB/s, about 312 TFLOPS dense BF16): reading the weights takes at least 13.5 GB ÷ 2.0 TB/s ≈ 6.7 ms, so at most about 148 tokens per second; computing needs about 1.35×10¹⁰ floating-point operations ÷ 312×10¹² ≈ 0.04 ms. Reading is over a hundred times slower than computing. This is called being memory-bound.

批处理改变这个比例：同时为 B 个请求各生成一个 token 时，权重只需读一遍，就能用于 B 个向量，计算量变为 B 倍而读取量几乎不变。所以在一定范围内，增大批次几乎“免费”地提高总吞吐量（7.5）。

Batching changes this ratio: generating one token for each of B requests at once reads the weights once and uses them for B vectors, so compute grows B-fold while weight reads stay almost the same. Within a range, larger batches raise total throughput almost “for free” (7.5).

Quantization's effect on quality depends on the model, method and task: 8-bit usually loses very little; 4-bit loses little on many benchmarks but can matter on some tasks; 3-bit and below usually need more elaborate methods. 7.3

KV 缓存：存下过去的 K 和 V，而不存 QThe KV Cache: Keep Past K and V, but Not Q

≈ 14 min前置：5.4、6.7Prerequisites: 5.4, 6.7

1问题The problem

按 6.7 的循环，每生成一个 token 都对整个上下文重新做前向计算。上下文有 1000 个 token 时，生成第 1001 个 token 要处理 1001 个位置，其中 1000 个位置的计算和上一步完全一样。这是巨大的浪费。

Following the loop of 6.7 naively, every new token reruns the forward pass over the whole context. With 1000 tokens of context, producing token 1001 processes 1001 positions, 1000 of which repeat the previous step exactly. That is an enormous waste.

2为什么可以缓存，缓存什么Why caching works, and what to cache

因果掩码保证：过去的位置永远看不到后来的 token。所以新 token 的到来不会改变任何过去位置在任何一层的计算结果，包括它们的 K 和 V。生成新 token 时，真正需要的是：新位置的 q（去和所有 k 比较），以及所有位置的 k 和 v（被比较和被加权）。过去位置的 q 只在当时计算它们自己的输出时用过一次，之后再也不需要。因此：每层把每个位置的 K、V 存下来，新位置只需计算自己的 q、k、v，把 k、v 追加进缓存，再用自己的 q 对整个缓存做注意力。

The causal mask guarantees that past positions never see later tokens. So a new token does not change any past position's results at any layer, including their K and V. Generating a new token needs: the new position's q (to compare against every k), and every position's k and v (to be compared and weighted). Past positions' q vectors were used once, to compute their own outputs, and are never needed again. So each layer stores every position's K and V; the new position computes only its own q, k, v, appends k and v to the cache, and attends with its q over the whole cache.

In standard multi-head attention every query head has its own K and V head. Multi-query attention (MQA, Shazeer 2019) makes all query heads share one K/V head; grouped-query attention (GQA, Ainslie et al. 2023) compromises: each group of query heads shares one K/V head. Llama 3.1 8B has 32 query heads and 8 KV heads, so every 4 query heads share one, and the KV cache shrinks to 1/4. W_K and W_V shrink accordingly (slightly fewer parameters). The cost is a slight loss of expressiveness; the paper reports GQA quality close to standard multi-head attention. For a serving system this directly means about 4× more context or concurrency in the same memory.

预填充与解码；首 token 延迟、逐 token 延迟与吞吐量Prefill and Decode; Time to First Token, Per-Token Latency and Throughput

≈ 12 min前置：7.3、7.1Prerequisites: 7.3, 7.1

1两个阶段Two phases

预填充：把整个提示一次性送入模型，所有提示位置并行计算（像训练的前向计算一样），为每层填满 KV 缓存，并由最后一个位置给出第一个生成 token 的分布。这是矩阵乘矩阵 [n, d] × [d, k]，每读一次权重做 n 份计算，通常是计算受限。解码：每步只处理一个新位置（每个请求），读入全部权重和该请求的整个 KV 缓存，只做一个向量的计算，通常是访存受限（7.1）。

Prefill: feed the whole prompt in at once; all prompt positions are computed in parallel (like a training forward pass), filling every layer's KV cache, and the last position gives the distribution for the first generated token. This is matrix-times-matrix [n, d] × [d, k], doing n computations per weight read, and is usually compute-bound. Decode: each step processes one new position (per request), reading all weights and that request's whole KV cache to compute a single vector, and is usually memory-bound (7.1).

深入 D6（可选，约 12 分钟）：算术强度与 FlashAttentionDeeper D6 (optional, about 12 min): arithmetic intensity and FlashAttention

算术强度 = 每从显存读一个字节所做的浮点运算次数。硬件也有一个“平衡点”：峰值算力 ÷ 带宽（A100 约 312×10¹² ÷ 2×10¹² ≈ 156 次/字节）。工作负载的算术强度低于平衡点就是访存受限，高于则是计算受限。批量为 1 的解码中，每个 BF16 权重（2 字节）只做 2 次运算，强度约为 1，远低于 156；批量为 B 时约为 B；预填充 n 个 token 时约为 n。这就是解码访存受限、预填充计算受限的定量解释（这一“屋顶线”模型来自 Williams 等 2009）。

Arithmetic intensity = floating-point operations per byte read from memory. Hardware has a balance point too: peak compute ÷ bandwidth (A100: about 312×10¹² ÷ 2×10¹² ≈ 156 operations per byte). A workload below the balance point is memory-bound; above it, compute-bound. In batch-1 decode each BF16 weight (2 bytes) is used for 2 operations, an intensity of about 1, far below 156; with batch B it is about B; prefilling n tokens gives about n. That is the quantitative reason decode is memory-bound and prefill compute-bound (this “roofline” model is from Williams et al. 2009).

FlashAttention（Dao 等 2022）把同样的道理用于注意力：朴素实现会把 [n, n] 的分数矩阵写入显存再读回来做 softmax，搬运量随 n² 增长。FlashAttention 把 Q、K、V 分块读入 GPU 片上的高速小存储，在块内完成分数、softmax（用一种可逐块更新的技巧）和加权求和，从不写出完整的 [n, n] 矩阵。计算结果与朴素实现相同（在浮点误差范围内），但显存读写大幅减少，长上下文时尤其明显。

FlashAttention (Dao et al. 2022) applies the same idea to attention. A naive implementation writes the [n, n] score matrix to memory and reads it back for softmax, so data movement grows with n². FlashAttention loads Q, K, V tiles into small, fast on-chip memory and computes scores, softmax (using a trick that can be updated tile by tile) and the weighted sum inside the tile, never writing out the full [n, n] matrix. Results match the naive implementation (within floating-point error), but memory traffic drops sharply, especially for long contexts.

深入 D8（可选，约 8 分钟）：推测解码Deeper D8 (optional, about 8 min): speculative decoding

既然解码每步主要花在读权重上，处理 1 个位置和处理 5 个位置的时间差不多。推测解码（Leviathan 等 2023；Chen 等 2023）利用这一点：用一个小而快的“草稿模型”连续猜出 k 个 token，再让大模型一次前向同时检查这 k 个位置；按一种特定的接受规则保留与大模型分布相符的前缀，并在第一个不符处由大模型重新采样。论文证明，输出分布与只用大模型完全相同，但当草稿猜得准时，大模型的前向次数明显减少，延迟下降。

Since each decode step is dominated by reading weights, processing 5 positions takes about as long as processing 1. Speculative decoding (Leviathan et al. 2023; Chen et al. 2023) exploits this: a small, fast draft model guesses k tokens in a row, then the large model checks all k positions in one forward pass; a specific acceptance rule keeps the prefix consistent with the large model's distribution and resamples from the large model at the first mismatch. The papers prove the output distribution is identical to using the large model alone, but when the draft guesses well, the large model runs far fewer passes and latency drops.

1问题The problem

“The model is 16 GB and my GPU has 24 GB, so it should fit?” Not necessarily. Runtime memory = weights + KV cache + activations and workspace + framework overhead. The last three vary with context length, concurrent requests and engine settings, and can be as large as the weights or larger.

深入 D7（可选，约 10 分钟）：PagedAttention 与连续批处理Deeper D7 (optional, about 10 min): PagedAttention and continuous batching

问题一：碎片。如果为每个请求按最大长度预留一整块连续的 KV 空间，而多数请求用不满，大量显存就被浪费。PagedAttention（Kwon 等 2023，vLLM 的核心）借鉴操作系统的分页：把 KV 缓存切成固定大小的块（如每块 16 个 token），按需分配，用一张表记录每个请求的块在哪里，注意力计算按表读取。这显著减少浪费，并允许共享相同前缀的请求共用块。

Problem one: fragmentation. Reserving one contiguous KV region per request at maximum length wastes much memory, since most requests never fill it. PagedAttention (Kwon et al. 2023, the core of vLLM) borrows paging from operating systems: the KV cache is split into fixed-size blocks (e.g. 16 tokens each), allocated on demand, with a table recording where each request's blocks are; attention reads through the table. This greatly reduces waste and lets requests with a common prefix share blocks.

问题二：批次里的快慢不齐。静态批处理要等批次中最长的请求结束，才能开始下一批。连续批处理（Yu 等 2022 的 Orca 提出的迭代级调度）在每一个解码步重新组批：完成的请求立即退出，新请求立即加入（先做它的预填充）。GPU 因此一直保持较高利用率。现代推理引擎普遍采用这类调度。

Problem two: uneven lengths in a batch. Static batching waits for the batch's longest request before starting the next batch. Continuous batching (the iteration-level scheduling proposed in Orca, Yu et al. 2022) re-forms the batch at every decode step: finished requests leave immediately and new ones join (after their prefill). The GPU stays busy. Modern inference engines widely use this kind of scheduling.

(b) One NVIDIA GPU: vLLM plus the original weight directory from Hugging Face, e.g. vllm serve meta-llama/Llama-3.1-8B-Instruct, which starts an OpenAI-compatible server. (c) For learning: load the model with transformers in Python and call generate; easiest to inspect step by step, lowest throughput. Check each project's current documentation for exact commands and flags.

7.7

张量并行、流水线并行与数据并行Tensor, Pipeline and Data Parallelism

≈ 8 min前置：7.5Prerequisites: 7.5

当模型放不进一张卡，或一张卡的吞吐量不够时，就要用多张 GPU。三种方式拆的东西不同：

When a model does not fit on one GPU, or one GPU's throughput is not enough, several GPUs are used. The three schemes split different things:

拆什么What is split通信Communication解决什么What it solves
数据并行Data parallelism不拆模型：每张卡一份完整副本，各自处理不同的请求（推理）或不同的数据批次（训练）Nothing in the model: each GPU holds a full copy and handles different requests (inference) or data batches (training)推理时几乎没有；训练时每步汇总梯度Almost none in inference; gradient averaging each step in training吞吐量；不解决“放不下”Throughput; does not help a model that will not fit

它们可以组合：例如一台 8 卡服务器内用张量并行放下一个 70B 模型，再在多台服务器之间做数据并行以扩大吞吐量。部署配置里的 tensor_parallel_size、pipeline_parallel_size 就是在选择这些方式（8.2）。

They combine: for example, tensor parallelism within an 8-GPU server to fit a 70B model, and data parallelism across servers for throughput. Settings such as tensor_parallel_size and pipeline_parallel_size in deployment configs choose among these (8.2).
